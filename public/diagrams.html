ML Prediction Lifecycle

  • 1
    Background Training
    A continuous daemon thread trains regression models hourly using structured historic Firestore entries.
  • 2
    Check-in Query
    A patient requests availability metrics; the Node Express server routes parameters to the ML Flask service.
  • 3
    State Hybridization
    For same-day requests, the server polls real-time live queues, adjusting forecast wait times based on elapsed duration.
  • 4
    Model Inference
    For future bookings, the GradientBoosting model evaluates clinic load & services to supply wait forecasts.

Onboarding Milestones

  • 1
    Google Places Search
    Admin inputs clinic location; Google Places API is queried to fetch coordinates, address details, and location identifiers.
  • 2
    Operating Schedules
    Admin sets standard hours and custom lunch windows, submitting configurations to the node server.
  • 3
    Database Provisioning
    The Express controller constructs standard schemas and establishes database collections in Firestore.
  • 4
    Services Seeding
    Custom service configurations (durations, pricing, triage weight) are seeded and linked to the clinic.

    actor Patient as Patient (Client Portal)
    participant Backend as Node.js Express Server
    participant ML as Python Flask ML Service
    database Firestore as Firebase Firestore DB
    participant Disk as Local Saved Models (.pkl)

    Note over ML, Firestore: Continuous Background Learning (Hourly)
    loop Every 3600 seconds
        ML->>Firestore: Fetch completed queue history & appointments
        Firestore-->>ML: Return historical dataset
        ML->>ML: Run Cyclic Feature Encoding (Sin/Cos day/hour)
        ML->>ML: Train Gradient Boosting Regressors
        ML->>Disk: Persist trained models & mappings to disk
    end

    Note over Patient, Disk: Real-time Wait-Time Prediction request
    Patient->>Backend: GET /api/availability?clinicId=C1&date=YYYY-MM-DD
    Backend->>ML: GET /predict-waittime?clinicId=C1&date=YYYY-MM-DD&timeSlot=09:00&serviceId=S1&priority=1
    
    alt Target Date is TODAY
        ML->>Firestore: GET /clinics/C1/queues/today/queueItems
        Firestore-->>ML: Return active queue list
        ML->>ML: Calculate live duration bounds (elapsed consult times + waiting queues)
    else Target Date is in the FUTURE
        ML->>ML: Load models from cached disk persistence
        ML->>ML: Predict busyness (hourly clinic load)
        ML->>ML: Predict consultant duration (department & priority)
        ML->>ML: Estimate wait-time = predicted_patients * avg_duration
    end
    
    ML->>ML: Apply +/-15% confidence margins and label category
    ML-->>Backend: Return JSON (estimatedWaitTime, waitTimeRange, waitLabel)
    Backend-->>Patient: Return aggregated availability & wait-time metrics
